# 运维人员的 70% 时间花在"找信息"上
## 而非"解决问题" —— 传统运维入口分散、操作繁琐

### 痛点 1：多系统切换低效
- 工单系统、监控平台、排班表分散在 3~5 个独立系统中
- 一次故障排查需要切换 4 次页面，人均耗时 15 分钟
- 深夜值班时不便打字，但现有运维工具仅支持键鼠操作

### 痛点 2：语音交互缺失
- 82% 的一线运维表示夜间更希望通过语音完成查询和操作
- 传统系统无语音输入/输出能力，手忙脚乱成为常态

### 痛点 3：敏感操作缺乏安全护栏
- 误删工单、误改排班缺乏二次确认机制
- 0.3% 的操作失误造成 30% 的额外工作量
- 无状态机管控，任何操作都可以一步执行、无法撤销

### 痛点 4：敏感数据不敢上云
- 运维数据涉及生产环境敏感信息
- 云端 LLM 存在合规风险与网络依赖

# 全离线 + 本地大模型：为什么不是云端方案？
## 运维数据涉及生产环境敏感信息，云端 AI 存在数据泄露风险与网络依赖

| 维度 | 云端 LLM 方案 (GPT/文心) | 轻言OPS：本地 Ollama + qwen3:8b |
|------|--------------------------|--------------------------------|
| 数据安全 | 数据出境，合规风险 | 数据不出本地，100% 内网运行 |
| 网络依赖 | 断网即不可用 | 全离线运行，无需外网 |
| 响应延迟 | 网络波动 2~5s | 本地推理 0.5~2s |
| 使用成本 | API 按 token 计费，月均数千元 | 零费用，硬件一次投入 |
| 语音识别 | 依赖云端 ASR，同样有数据风险 | FunASR 离线识别，无数据传输 |
| 语音合成 | 云端 TTS | sherpa-onnx / SAPI 三引擎离线 |

> **结论：轻言OPS 是业内少有的从 LLM 推理 → 语音识别 → 语音合成 → 数据库全链路离线运行的运维助手。**

# 核心创新 ①：全离线 AI 技术栈
## 4 个独立 AI 引擎协同工作，全部运行在本地，不依赖任何外部 API

### 引擎层

| 引擎 | 技术方案 | 角色 | 模型大小 | 延迟 |
|------|----------|------|----------|------|
| LLM 推理 | Ollama + qwen3:8b (Q4 量化) | 决策大脑 | 5.2 GB | ~1s |
| 语音识别 | FunASR paraformer-zh + VAD + 标点 | 耳朵 | ~1 GB | ~200ms |
| 语音合成 | sherpa-onnx VITS / SAPI / edge-tts | 嘴巴 | ~345 MB (3 模型) | ~300ms |
| 数据存储 | SQL Server 2019+ (pyodbc, 8 连接池) | 记忆 | - | <50ms |

### 协作流程
```
用户语音 → ASR 识别 (200ms) → 数字归一化 → LLM 意图解析 (~1s) → 业务执行 → TTS 合成 (300ms) → 语音回复
```

### 关键数据
- 模型预加载后首次对话响应 < 1 秒（Ollama keep_alive=-1 常驻）
- 13 步一键启动完成全链路初始化
- GPU 加速（RTX 4060 8GB 显存）可流畅推理
- TTS 注册表：**zh-ll（5 音色）+ melo（中英混合女声，默认）+ fanchen（男声，可选）**

# 核心创新 ②：双重意图解析 + FSM 安全护栏
## 11 类意图 × 双重策略 × 5 状态机 = 精准且安全的决策大脑

### 双重意图解析策略

**第一步：规则预检（正则匹配，< 50ms）**
- 覆盖排班查询 / 导航 / 排班操作 / 工单 ID 标准化等高频场景
- 命中 → 直接返回，**绕过 LLM**，零 token 消耗
- 支持工单 ID 归一化：`TKT202608310005` → `TKT-20260831-0005`

**第二步：LLM 解析（Ollama qwen3:8b）**
- complex 意图交给大模型处理
- 严格 JSON 输出，temperature=0.1，max_tokens=500
- 6 层 JSON 容错（截断补全 / 栈法提取 / 正则兜底 / 无上下文降级重试）
- 强制阿拉伯数字输出，禁止"两千零二十六"等中文数字幻觉

### FSM 5 状态安全护栏

| 状态 | 说明 | 转移条件 |
|------|------|---------|
| IDLE | 初始状态 / 操作完成 | 接收输入 → PROCESSING |
| PROCESSING | LLM 意图解析中 | 解析完成 → REPLYING 或 AWAITING_CONFIRMATION |
| REPLYING | 生成回复中 | TTS 完成 → IDLE |
| AWAITING_CONFIRMATION | 等待用户确认（30s 超时自动取消） | 用户确认 → EXECUTING / 用户取消 → IDLE |
| EXECUTING | 执行 DB 写操作 | 业务完成 → IDLE |

### 关键指标
- 删除 / 指派 / 排班 默认需二次确认，可在参数配置中关闭
- 30 秒超时自动取消，防止死锁
- 指代消解支持最近 8 轮连续对话上下文
- 工单 ID 多格式容错：口述数字、缺短横线、大小写都可识别

# 核心创新 ③：语音交互全链路 + 三引擎 TTS 降级
## 从"听到"到"说出"：端到端语音交互只需 3 步

### 全链路流程

```
① 语音采集       ② ASR 识别         ③ LLM 决策         ④ 业务执行        ⑤ TTS 合成
VAD 自动检测     FunASR              Ollama             Flask + DB        三引擎降级
手动/连续聆听    paraformer          qwen3:8b           二次确认护栏       sherpa→SAPI
模式自选         WebM→WAV            严格 JSON          8 连接池          →edge-tts
                16kHz mono          temperature        事务回滚          离线优先
                数字归一化          0.1                                 数字按位读
                耗时 1~2s                                               "45.2%" → "百分之四十五点二"
```

### TTS 三引擎降级链

```
sherpa-onnx VITS (神经网络, 离线, 7 音色, ~345MB, 默认 Melo 中英混合女声)
     ↓ 加载失败
Windows SAPI (系统自带, 离线兜底, 自动枚举已安装语音: 晓晓/云希/晓伊等)
     ↓ TTS_MODE=auto 时启用
edge-tts (微软在线神经网络, 音色丰富, 在线)
```

### TTS 智能数字播报
- **小数字（1~3 位）**：保留原样 → "二百七十七"（自然朗读）
- **大数字（≥4 位，如工单号 / 年份）**：按位读 → "二零二六"（防止念成"两千零二十六"）
- **百分比**：自动补全 → "CPU 百分之45.2"（防止吞掉百分号）

### 双层 VAD 持续聆听算法
- **前端 VAD（1.8s 静音）**：每 50ms 采样 RMS 音量，动态噪声基线校准，控制录音停止
- **后端 VAD（2400ms 句尾）**：FunASR fsmn_vad 模型精确判断句子结束
- 灵敏度 2.5 倍阈值判定，最短录音 800ms 过滤瞬时噪声

## 双击 startup.bat → 13 步全自动 → 浏览器打开即用

### 13 步启动流程

| 步骤 | 内容 | 必需/可选 |
|------|------|----------|
| [1/13] | 检查 Python 3.12+ 环境 | 必需 |
| [2/13] | 检查 ffmpeg & 自动加入 PATH | 必需 |

| [6b/13] | 下载 sherpa-onnx 可选扩展 TTS 模型（fanchen 繁辰男声） | 可选 |
| [7/13] | 检查 Node.js 22.18+ 环境 | 必需 |
| [8/13] | 安装前端依赖 (npm install) | 必需 |
| [9/13] | 检查 Ollama 服务 | 必需 |

| [13/13] | 同时启动后端 (5000) + 前端 (5173) | 必需 |

### TTS 模型下载智能策略
- **已有则跳过**：检测 `C:\sherpa-tts\<模型>\model.onnx` 已存在则直接 `[SKIP]`
- **没有则下载**：curl 断点续传（--retry 10 -C -）+ 进度可见
- **失败则降级**：melo 失败 → zh-ll，zh-ll 失败 → Windows SAPI

### 启动结果
```
前端：http://localhost:5173 → 浏览器打开即进入系统
后端 API：http://localhost:5000
```

### 硬件要求
- CPU：8 核及以上（推荐）
- 内存：16 GB 及以上（建议 32 GB）
- 显卡：RTX 4060 8GB 显存及以上（推荐 GPU 加速）

# 总结与 Q&A
## 轻言OPS — 让运维工作"张口就来"

### 三大核心价值

- **智能**：大模型驱动决策，LLM 解析 11 类意图，语音对话零门槛
- **安全**：全离线本地运行，数据不出内网，FSM 状态机二次确认护栏
- **便捷**：一键启动 13 步、模型预加载常驻、工单/排班/监控一站式

### 五大技术亮点
1. **全离线 AI 技术栈**：LLM + ASR + TTS + DB 全链路无外网依赖
2. **双重意图解析**：规则预检 + LLM 解析，兼顾速度与灵活性
3. **FSM 安全护栏**：5 状态机 + 二次确认 + 30s 超时，敏感操作可防误操作
4. **三引擎 TTS 降级**：sherpa → SAPI → edge-tts，任意环境都有声音
5. **智能数字处理**：ASR 中文数字归一化 + TTS 数字按位 / 自然读切换
